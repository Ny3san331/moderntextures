# FixTextures: agent notes

- This is a three-module Gradle project (`core`, `generator`, `plugin`) using Java 25 and Gradle wrapper 9.2.1. On Windows, run `./gradlew.bat test :generator:fatJar :plugin:jar`; for one test use `./gradlew.bat :generator:test --tests dev.fixtextures.generator.PackGenerationTest`. `:generator:fatJar` creates the runnable `generator/build/libs/FixTextures-Generator.jar`; `:plugin:jar` embeds core in `plugin/build/libs/FixTextures.jar` (Paper/Via APIs remain `compileOnly`).
- `generator.Main` reads official client JARs via `Downloads`/`Assets`, uses pinned Prismarine/Via mapping data from `mappings.json`, and writes ZIPs, reports and `manifest.json` to `--output` (default `packs/`; downloads go to `--cache`). `--targets 1.16.5` is a focused generation check; `--all` generates all 51 profiles and downloads substantial data. `mcasset.cloud` is currently a reference for comparing assets, **not** the implemented download/index backend; do not describe a proposed index-based redesign as already implemented.
- `generator.Main` preserves entries from an existing output manifest when regenerating selected targets. `package.ps1` checks SHA-1 for every manifest-listed ZIP and needs all matching reports present; run it with `powershell -NoProfile -ExecutionPolicy Bypass -File package.ps1` after generating packs and building both JARs. `packs/`, `cache/`, `dist/` and `packs-test/` are ignored; `dist/github-pages/` is a separate Git checkout, not source tracked on this branch. Do not remove previously published hashed ZIPs (old URLs may remain in use).
- `plugin.FixTexturesPlugin` loads `plugins/FixTextures/manifest.json` and config into memory at enable/reload; it does **not** fetch a remote manifest. An empty packaged manifest requires replacement or a local bundle. Variant directory `variants/<name>/manifest.json` can override the root `default` variant. `plugin.yml` supplies `/fixtextures` aliases `/ft` and `/mt`. Check `plugin/src/main/resources/config.yml` before changing URL/HTTP behavior.
- The plugin uses public Paper/ViaVersion APIs; keep pack generation outside server runtime and do not change ItemStacks, Via configs or `server.properties` automatically. On legacy clients another resource-pack sender can replace this pack; only `LOADED` status confirms the client's report. For new items, models select by CustomModelData, never display name; legacy predicates mean `>=`, so reset overrides after exact values.
- Resource packs cannot restore distinct world-block identities after protocol translation (e.g. amethyst mapped to purpur), implement modern mob renderers/weapon mechanics, or extend the 1.16.5 Y=0..255 height range. Model/UV compatibility needs client-side validation; generated ZIP and HTTP smoke tests are not visual certification. See `docs/CORRECOES-1.0.1.md` for known 1.16.5 issues.
